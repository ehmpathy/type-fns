# case 1 — a branded primitive survives, nested in a payload

> cell **A14** · `primitive-branded × assign-back × nested` · feel **happy** · care **critipath** ·
> the densest cell in the box
>
> ⚠️ without the fix, this cell is `sharp` and its error misleads. the fix moves the feel, never the
> cell.

## .the narrative

kai maintains `svc-chat`. she adds a paged read: `getThreadsByParticipant` takes a payload whose
`page.range.since.lastMessageAt` is an `IsoTimeStamp` — a branded string from `iso-time`. she
wires it like every other endpoint:

```ts
genLambdaEndpoint.forAsk({
  payload: getThreadsByParticipantPayloadSchema,
  invoke: async ({ payload }) => await query(payload),
});
```

without the fix, `tsc` rejects it. the error claims her `IsoTimeStamp` is not an `IsoTimeStamp`,
and offers a wall of `String.prototype` members — `readonly charAt`, `readonly padStart`, … — with
`readonly _dglo: "iso-time.IsoTimeStamp"` at the bottom.

she checks her import, her schema, and the `iso-time` changelog. all correct.

the cause is two repos away and one word wide: `FrozenDeep` has no primitive arm, so
`string & OfGlossary<…>` satisfies `T extends object` and maps like a record. the runtime freeze
returns early on `typeof value !== 'object'`, so at run time the stamp is untouched. type and
mechanism disagree; only the type complains.

she ships a pnpm patch — one line, carried in her repo, for an upstream defect.

with the fix, the same three lines compile. the stamp goes in a stamp and comes out a stamp. the
patch is deleted.

### the aha

> "frozen" should mean *you cannot change it*, never *it stops to be what it was*.

a primitive has no interior to freeze. to leave it alone is the only honest answer.

## .the bdd sketch

```gherkin
given a branded primitive nested inside a payload object
  and the payload slot is typed FrozenDeep<TPayload>

  [t0] when the author declares the payload shape
       then FrozenDeep<{ page: { since: Stamp } }>
            maps the since slot to Stamp, not to a mapped record

  [t1] when the author assigns the frozen payload back to the un-frozen shape
       then it compiles
        and `since` is still assignable to a parameter typed Stamp

  [t2] when the author forwards the whole payload to a query typed on the un-frozen shape
       then it compiles

  [t3] when the author attempts to WRITE through the frozen payload
       then tsc refuses — the passthrough loosened identity, never the guarantee
```

```ts
// [t0] + [t1] — the clamp, as it will land in src/types/FrozenDeep.test.ts
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };

const nested: { readonly since: Stamp } = {} as FrozenDeep<{ since: Stamp }>;
const backOut: Stamp = nested.since;

// [t2] — the svc-chat shape, forwarded whole
const query = (_input: { since: Stamp }): void => undefined;
query({} as FrozenDeep<{ since: Stamp }>);

// [t3] — the guarantee is intact
// @ts-expect-error - the slot is readonly
({} as FrozenDeep<{ since: Stamp }>).since = '' as Stamp;
```

`[t1]` is the minimal proof; `[t2]` is the lived one — closest to what kai wrote, and the loudest
failure without the fix. both belong in the suite.

## .why it is a critipath

- **freq** — every branded primitive in every lambda payload of every service that adopts
  `sdk-aws-lambda`. `iso-time` exports 10 branded string primitives (`IsoTimeStamp.ts` 4 +
  `IsoTimeFloat.ts` 6); `iso-price` exports 2 (`IsoPriceWords`, `IsoPriceHuman`). twelve, before
  any repo's own brands.
- **cost** — `tsc` fails, so adoption stops. the workaround is a vendored pnpm patch: a fork of a
  dependency, carried indefinitely, visible only to its author.
- **diagnosis** — the error names `IsoTimeStamp` on both sides and calls them different. an
  author's first four guesses all land in their own repo.
