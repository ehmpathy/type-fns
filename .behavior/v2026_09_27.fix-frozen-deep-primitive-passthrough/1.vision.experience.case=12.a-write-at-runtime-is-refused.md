# case 12 — a write at runtime is refused

> **C03** `[t0]` and **C09** `[t1]`, both sharp·criti.

## .the narrative

jo consumes a payload the sdk froze with `asFrozenDeep`. his own code holds the original reference,
typed mutable, so `tsc` has no squiggle to show him. he bumps a page limit in place:

```ts
input.page.limit = 50;   // TypeError: Cannot assign to read only property 'limit'
```

the engine refuses it, and the limit holds at 10. the type could not see this write; the runtime
could.

later he records a seen channel on the payload's map:

```ts
input.seen.set('push', 2);
```

a bare `Object.freeze` would let this through — a `Map` keeps its entries in an internal slot, out
of a freeze's reach. `asFrozenDeep` shadows the mutator, so the call throws:

```
✋ ConstraintError: a frozen Map refuses .set()
{ "kind": "Map", "mutator": "set", "hint": "copy it first, then mutate the copy: new Map(frozen)" }
```

the error names the kind, the mutator, and the copy that fixes it. the map holds.

### the aha

> the freeze holds where the type can not look, and where a bare freeze would leak.

## .why a critipath

if `[t1]` broke, a consumer would mutate a "frozen" payload with no signal — the silent drift the
wish's whole premise exists to prevent.
