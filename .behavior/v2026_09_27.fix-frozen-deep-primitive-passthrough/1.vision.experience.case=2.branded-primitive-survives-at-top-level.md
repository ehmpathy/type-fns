# case 2 — a branded primitive survives at the top level

> cell **A13** · `primitive-branded × assign-back × top` · feel **happy** (without the fix: `sharp`,
> ⚠️ misleads) ·
> care **critipath** · the minimal reproduction

## .the narrative

rey maintains type-fns. before the fix, she wants the smallest case that fails, to watch it flip.

```ts
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };
const a: FrozenDeep<Stamp> = '' as Stamp;
```

then the line that proves identity survives, not merely that the assign is accepted:

```ts
const b: Stamp = a;
```

without the fix, that last line fails — a bare branded string, no nest, no lambda, handed straight
to the type that claims to leave it alone. case 1 is this same defect, wrapped in a payload and two
repos of distance.

### the aha

> the defect needs no lambda, no sdk, no nested slot. it is a property of the type and one
> intersection.

⇒ so the fix belongs in type-fns, not sdk-aws-lambda. the bug is about what "deep readonly" means
for a value with no depth.

## .the bdd sketch

```gherkin
given a branded primitive — an intersection of a primitive and a tag object

  [t0] when FrozenDeep is applied to it directly
       then the result accepts the branded value

  [t1] when the result is assigned back to the brand
       then it compiles — identity survived the round trip

  [t2] when a plain, unbranded primitive is passed instead
       then it behaves identically — no regression on the base case

  [t3] when the primitive arm is removed from the type
       then [t1] goes red — the clamp bites (see case 7)
        and [t0] stays green — a forward assign still compiles; only the way back fails
```

```ts
// [t0] + [t1] — verbatim from the wish's clamp
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };

const a: FrozenDeep<Stamp> = '' as Stamp;
const b: Stamp = a;

// [t2] — the base case is untouched
const plain: FrozenDeep<string> = 'hello';
const backToString: string = plain;
```

## .why it is a critipath, beside case 1

| | case 1 (nested) | case 2 (top) |
|---|---|---|
| proves | the defect as it is **lived** | the defect as it **is** |
| blast radius | adoption of a whole sdk | the type's own contract |
| diagnostic value | why it was hard to find | that one line fixes it |
| in the clamp | `[t2]` — the forwarded payload | `[t0]`, `[t1]` — the wish's first two assertions |

the wish says both assertions go red when the primitive arm is removed. only `[t1]` does: the
defect breaks the way back, never the forward assign (case 7, `.the wish's phrase, read
precisely`). `[t1]` is the proof-of-bite; `[t0]` is the precondition that gives `[t1]` its sense.
