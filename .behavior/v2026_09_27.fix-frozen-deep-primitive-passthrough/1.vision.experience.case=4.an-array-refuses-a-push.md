# case 4 — an array refuses a push

> cells **A37** `[t0]` · **A38** `[t3]` · `array × write-method × top/nested` ·
> feel **sharp** · care **critipath** `[t0]` **·** care **alterpath** `[t3]` ·
> a **declared composite** (see the inventory's composite table)

## .the narrative

sam handles an sqs batch. the envelope hands over `records`, frozen. sam reaches for the cheapest
move:

```ts
invoke: async ({ records }) => {
  const kept = records;
  kept.push(makeSyntheticRetry());   // "one more, for the retry"
  return await process(kept);
};
```

`kept` is `records`. the push mutates the envelope the sdk reads *after* `invoke` returns — the set
its unknown-id guard checks against. with the runtime freeze, the push throws. without it, the push
succeeds and the batch reports an `itemIdentifier` sqs cannot match, so a message sam meant to save
is deleted on a successful invocation.

`FrozenDeep` refuses the line:

```
Property 'push' does not exist on type 'readonly SqsRecord[]'.
```

sam writes `[...records, makeSyntheticRetry()]` — what he meant — and the envelope is untouched.

### the aha

> an array's mutation surface is its **methods**, not its properties. a readonly *property* catches
> none of this; `ReadonlyArray` does, and the array arm is what reaches for it.

⇒ so the array arm sits above the object arm. without it, an array falls into the object arm and
maps to `{ readonly 0: T; readonly length: number; readonly push: … }` — `push` still present, and
no `readonly` on a method ever refused a call.

## .the bdd sketch

```gherkin
given an array typed FrozenDeep

  [t0] when the author calls a mutator method on it
       then tsc refuses — push is absent from ReadonlyArray

  [t1] when the author calls a non-mutator method on it
       then it compiles — map, filter, slice all survive

  [t2] when the author indexes into it
       then it compiles — reads are untouched

  [t3] when the array is NESTED inside a frozen object
       then the mutator is still refused at that depth

  [t4] when the array holds a branded primitive
       then the item type is still the brand, not a mapped record
```

```ts
// [t0] — the wish's fourth clamp assertion, verbatim
// @ts-expect-error
({} as FrozenDeep<number[]>).push(1);

// [t1] + [t2] — reads and pure methods survive
const doubled: readonly number[] = ({} as FrozenDeep<number[]>).map((n) => n * 2);
const first: number | undefined = ({} as FrozenDeep<number[]>)[0];

// [t3] — nested, measured as probe row I
// @ts-expect-error
({} as FrozenDeep<{ xs: number[] }>).xs.push(1);

// [t4] — the fix reaches inside the array too
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };
const stamps = {} as FrozenDeep<Stamp[]>;
const oneStamp: Stamp | undefined = stamps[0];
```

⚠️ **`[t4]` is outside the wish's clamp.** an array of branded primitives (cell **A31/A33**, item
type `primitive-branded`) is the same defect one container down, and no listed assertion covers it.

## .why it is a critipath

- **freq** — `records: FrozenDeep<TShapes['record'][]>` is a declared slot of every sqs envelope,
  the sdk's largest family.
- **cost** — a **deleted message on a successful invocation**: a forged `id` defeats the
  unknown-id guard, and sqs gets an identifier it cannot match.
- **the one real sink refusal** (case 5) — a readonly array refuses a mutable-array parameter; a
  readonly property does not. this arm carries more of the practical guarantee than the object arm.
