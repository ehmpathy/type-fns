# case 5 — a frozen value refuses a write, and a mutable-array sink

> cells **A33, A34** `[t0]` · **A53, A54** `[t1]` (the negative bound) ·
> `array × assign-back × top/nested`, against `object-plain × assign-back × top/nested` ·
> feel **sharp** · care **critipath** `[t0]` **·** feel **happy** · care **alterpath** `[t1]` ·
> the sink bound · a **declared composite** (see the inventory's composite table)

## .the narrative

ada adopts the sdk and takes its contract note at its word:

> `FrozenDeep<TInput>` makes `event` unassignable to every mutable parameter a handler forwards
> it to, so a handler must declare its sinks readonly.

so she expects this to fail:

```ts
const fulfil = (input: { qty: number }): void => { /* … */ };
invoke: async ({ payload }) => fulfil(payload);   // payload: FrozenDeep<{ qty: number }>
```

it compiles. to typescript, `{ readonly qty: number }` **is** a `{ qty: number }` — the checker
ignores `readonly` property modifiers in structural assignability. a deliberate unsoundness in
typescript, not a gap in the type (`appendix/groundwork.probe.readonly-variance.md`, rows A–C).

then she tries the sqs family:

```ts
const process = (input: { records: Record[] }): void => { /* … */ };
invoke: async ({ event }) => process(event);      // event.records: readonly Record[]
```

**that** fails. `ReadonlyArray<T>` is not a `T[]`, at any depth — one nested readonly array refuses
the whole object.

the real rule, narrower than the prose:

> `FrozenDeep` refuses **writes** everywhere. it refuses a **mutable sink** only where an array is
> in the shape.

the wisher's verdicts (F3, F6, F9) left this bound in place: the shipped type still hands a plain
object to a mutable object sink.

### the aha

> a `readonly` property refuses at the **write site**, never at the **hand-off**. an array is the
> one shape where readonly-ness is part of the type's identity, not a modifier on it.

⇒ the sdk's prose generalizes from its own envelopes, each of which holds an array
(`records: FrozenDeep<TShapes['record'][]>`). true there, false in general. type-fns ships to
everyone, so the jsdoc states the bound (F4).

## .the bdd sketch

```gherkin
given a value typed FrozenDeep

  [t0] when its shape contains an array and it is passed to a mutable-array sink
       then tsc refuses

  [t1] when its shape is a plain object and it is passed to a mutable-object sink
       then it COMPILES — the documented bound, clamped so it cannot be mis-promised

  [t2] when the author writes through it instead
       then tsc refuses, array or object alike

  [t3] when the sink declares itself readonly
       then it compiles either way — the cooperative path
```

```ts
// [t0] — an array refuses the sink, at top level and nested
const takesArr = (_input: number[]): void => undefined;
// @ts-expect-error - ReadonlyArray is not a mutable array
takesArr({} as FrozenDeep<number[]>);

const takesNested = (_input: { xs: number[] }): void => undefined;
// @ts-expect-error - one nested readonly array refuses the whole object
takesNested({} as FrozenDeep<{ xs: number[] }>);

// [t1] — THE BOUND. a plain object does NOT refuse. asserted, so the jsdoc cannot over-promise
const takesObj = (_input: { y: number }): void => undefined;
takesObj({} as FrozenDeep<{ y: number }>);          // compiles — measured, probe row B
takesObj({ y: 1 } as FrozenDeep<{ y: number }>);

// [t2] — the write refusal is total
// @ts-expect-error
({} as FrozenDeep<{ y: number }>).y = 1;

// [t3] — a readonly sink accepts either
const takesReadonly = (_input: { readonly xs: readonly number[] }): void => undefined;
takesReadonly({} as FrozenDeep<{ xs: number[] }>);
```

🔴 **`[t1]` asserts a case COMPILES — the only way to clamp a *bound*.** if a later author
"strengthens" `FrozenDeep` to refuse object sinks (a branded readonly, say), `[t1]` goes red and
forces the conversation, before the change breaks every handler that forwards an envelope.

## .why it is a critipath

- **freq** — every consumer who reads "frozen" and forms an expectation of what it refuses. formed
  once, relied on forever.
- **cost** — a **wrong mental model**. ada either over-defends (readonly-izes every sink, for no
  gain on object shapes) or under-defends (trusts an absent refusal). no error message corrects
  either.
- **the sdk's prose is the default belief.** without a clamp on the true bound, the next author
  copies the generalization into the jsdoc.
