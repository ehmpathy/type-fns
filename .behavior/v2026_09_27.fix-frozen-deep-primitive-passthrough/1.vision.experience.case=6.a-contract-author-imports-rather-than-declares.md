# case 6 — a contract author imports rather than declares

> cells **B01, B02** · `contract-author × obtain/declare` · feel **happy** · care **critipath** ·
> the adoption path the wish exists to open

## .the narrative

lin maintains `sdk-aws-lambda`. she needed a deep-readonly type, found none in her dependencies,
and wrote one at the top of `setEventFrozen.ts` — four arms and a careful jsdoc, beside the freeze
it types.

that kept contract and freeze in one file. it also gave the type **one author, one review, and one
repo's test shapes**. no envelope of hers carries a branded primitive in a slot her suite touches,
so the absent primitive arm shipped — until kai's payload hit it two repos downstream (case 1).

after this wish, lin deletes her declaration and writes one line:

```ts
import type { FrozenDeep } from 'type-fns';
```

`setEventFrozen` keeps the runtime freeze — that mechanism belongs beside her envelopes. only the
general half leaves: a deep-readonly type is not a lambda concept.

her re-export stays valid:

```ts
export type { FrozenDeep } from './domain.operations/genLambdaEndpoint/setEventFrozen';
// becomes
export type { FrozenDeep } from 'type-fns';
```

her own consumers see no break.

### the aha

> a general type in a specific package gets a specific package's test shapes. the defect was not
> a careless line — it was a **home** that could only see one repo's inputs.

⇒ type-fns already holds `withAssure`, `PickOne`, and `HasMaybe`. there, every consumer's shapes
exercise the type, and one fix reaches all of them.

## .the bdd sketch

```gherkin
given type-fns exports FrozenDeep from its package root

  [t0] when a contract author imports it by name
       then `import type { FrozenDeep } from 'type-fns'` resolves

  [t1] when they declare a slot with it
       then `payload: FrozenDeep<TPayload>` type-checks
        and behaves identically to their local declaration on every shape
        their suite already covers

  [t2] when they delete their local declaration and re-export the imported one
       then their downstream consumers see no break

  [t3] when their envelope carries a branded primitive
       then it now type-checks, where it did not before
```

```ts
// [t0] — the export must be reachable from the root, not a deep path
import type { FrozenDeep } from 'type-fns';

// [t1] — a slot, declared
interface InvokeInput<TPayload> {
  payload: FrozenDeep<TPayload>;
}

// [t3] — what the swap buys them
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };
const input: InvokeInput<{ since: Stamp }> = {} as never;
const since: Stamp = input.payload.since;
```

⚠️ **`[t0]` is not ceremony.** `src/types/ArrayWith.ts` ships in `dist` and is absent from
`src/index.ts`, so no consumer can import it by name. to a consumer, an unexported type is an
unwritten one. this route adds that export too (F7).

## .why it is a critipath

- **freq** — once per adopter, and every adopter passes through it. `sdk-aws-lambda`'s step 2 waits
  on this release; `svc-chat`'s pnpm patch goes with it.
- **cost** — miss the export line and the whole wish is unrealized; a perfect type is still
  unreachable.
- **it names the root cause.** case 1 is the symptom; this fixes the structural condition — a
  general type with a local home.

## .the release dependency

the done-when ends at **"released to npm, so `ehmpathy/sdk-aws-lambda` can import it."** this case
closes at a published version, not a green suite. release to prod is a **human gate** (`.bounds`),
so the route's last act hands the human a release.
