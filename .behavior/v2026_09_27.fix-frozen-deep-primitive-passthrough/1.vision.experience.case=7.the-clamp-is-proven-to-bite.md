# case 7 — the clamp is proven to bite

> cell **B09** · `maintainer × verify` · feel **sharp** · care **critipath** ·
> a done-when the wish states outright

## .the narrative

rey has written the type and the tests. the suite is green.

green proves the tests pass against the **fixed** type. it does not prove they fail against the
**broken** one. a test that passes either way reads as protection, guards no defect, and stops
anyone from authorship of a real one.

so rey dogfoods. she reverts one item — the primitive arm:

```ts
export type FrozenDeep<T> =
- T extends string | number | boolean | bigint | symbol | null | undefined
-   ? T
-   : T extends (...args: never[]) => unknown
+ T extends (...args: never[]) => unknown
      ? T
      : …
```

she re-runs `tsc`. it goes **red on exactly two lines, and neither is the first**. measured
(`appendix/groundwork.probe.clamp-bite.md`):

```
src/types/FrozenDeep.test.ts:13  Type 'FrozenDeep<Stamp>' is not assignable to type 'Stamp'
src/types/FrozenDeep.test.ts:16  Type 'FrozenDeep<{ at: Stamp; }>' is not assignable to
                                 type '{ readonly at: Stamp; }'
```

⚠️ **line 12 — `const a: FrozenDeep<Stamp> = '' as Stamp` — stays green**, correctly. the broken
type maps `Stamp` to a readonly record of every `String.prototype` member plus `_dglo`, which a real
`Stamp` satisfies. **the defect is one-directional**: a value goes in and cannot come back out.

⇒ expected result: **two red of five, first assertion green.** rey needs that count before she
reverts, or she cannot tell a clamp that bit from a botched revert.

she restores the arm and confirms green. three steps, two minutes, and the tests become evidence.

### the aha

> a clamp you have never seen fail is a guess with a green check next to it.

⇒ the repro that proves the fix is the clamp that keeps it. to keep it as a test costs no extra
effort.

## .the bdd sketch

```gherkin
given the FrozenDeep type with its primitive arm, and its suite green

  [t0] when the primitive arm alone is removed
       then tsc fails on EXACTLY two lines
        and they are the two assignability-BACK assertions (case 2 [t1], case 1 [t0])
        and the forward assignment stays green — the defect is one-directional

  [t1] when the arm is restored
       then tsc passes again

  [t2] when the OBJECT arm is loosened instead
       then the deep-write assertions go red (case 3 [t0], [t3])

  [t3] when the ARRAY arm is loosened instead
       then the push assertion goes red (case 4 [t0])
```

⚠️ `[t2]` and `[t3]` extend the wish, which names only the primitive-arm revert. each arm carries a
distinct guarantee; a bite on one proves naught about the others.

## .which assertions need the revert

`tsc` **fails on an unused `@ts-expect-error`**. so every negative assertion — case 3 `[t0]`,
case 4 `[t0]`, case 5 `[t0]` — clamps itself: if its refusal stops, the build breaks.

positive assertions have no such backstop. they pass when correct and also pass when the type
widens. the manual revert exists for them.

| assertion | green under the FIX | green under the BREAK | clamps? |
|-----------|--------------------|-----------------------|---------|
| any `@ts-expect-error` negative | ✅ | ⛔ unused directive | ✅ self-clamped |
| `const a: FrozenDeep<Stamp> = '' as Stamp` | ✅ | 🔴 ✅ | ⛔ **no** |
| `const b: Stamp = a` | ✅ | ⛔ | ✅ yes |
| `const c: { readonly at: Stamp } = …` | ✅ | ⛔ | ✅ yes |

⇒ row 2 is a correct assertion that clamps no defect on its own. only the revert shows that. this
table is the revert's output, not a prediction.

## .why it is a critipath

- **freq** — once per change to the type, forever. any author who touches an arm owes the check.
- **cost** — a false-green clamp hides other defects. `rule.require.clamp-edge-cases` calls it
  worse than an absent test.
- **the wish names it as a done-when**: *"remove the primitive check and the first two assertions
  go red."*

## 🔴 .the wish's phrase, read precisely

> *"remove the primitive check and **the first two assertions** go red"*

counted by statement, false: the first statement stays green. counted by block — `a` and `b` as
one assertion, `c` as the second — true. the precise form, for the test file's comments:

> remove the primitive arm and **the two assignability-back assertions go red** — `const b: Stamp = a`
> and the nested `const c`. the forward assignment stays green; the defect is one-directional.

⚠️ the wish exists to make the fix **falsifiable**. a maintainer who cannot match expected red-count
to observed has lost exactly that.

## .what execution owes

the revert leaves no artifact unless one is authored. execution records the exact `tsc` errors,
with line numbers, in its yield — **and the green line**: *"two red, line 12 green as expected."*
