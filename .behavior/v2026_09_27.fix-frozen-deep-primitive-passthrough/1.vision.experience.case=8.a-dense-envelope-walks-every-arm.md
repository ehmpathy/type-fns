## .why this case exists

cases 1–7 each exercise **one** arm. `define.experience._.metric=boundary-density`:

> a dense experience is the one **most likely to break**, *because* it crosses so many
> boundaries. each boundary is a failure point, and their interactions compound.

a real payload is a branded primitive **and** a nested object **and** an array, under one
`FrozenDeep`, forwarded in one line. this walk builds that shape and forwards it — and finds a wall
no single-arm case can. measured in `appendix/groundwork.probe.dense-envelope.md`.

## .the narrative

kai's payload from case 1 ships. a month later rio adds a peer endpoint — same shape, plus a
`tags: string[]` filter:

```ts
interface Payload {
  page: { range: { since: { lastMessageAt: IsoTimeStamp } } };
  tags: string[];                                          // ← the one new field
}

invoke: async ({ payload }) => await query(payload);
```

`tsc` rejects it. the measured message:

```
error TS2345: Argument of type '{ readonly page: { readonly range: { readonly since:
  { readonly lastMessageAt: Stamp; }; }; }; readonly tags: readonly string[]; }'
  is not assignable to parameter of type 'PayloadWithArray'.
  Types of property 'tags' are incompatible.
    The type 'readonly string[]' is 'readonly' and cannot be assigned to the
    mutable type 'string[]'.
```

rio knows the branded-primitive fix shipped, and the handler still fails. he concludes the fix did
not take.

🔴 **the error refutes him on its first line** — `readonly lastMessageAt: Stamp`. the stamp is a
`Stamp`. he skimmed past the expanded type to the red squiggle.

**the fix did land.** `tags` refuses: `readonly string[]` is not a `string[]`, so one nested readonly
array refuses the whole payload at the hand-off (case 5). the message names it on line 2.

two walls, one field apart:

| | the wall | cause | remedy |
|---|---------|-------|--------|
| kai (case 1) | the stamp is not a stamp | the absent primitive arm | **this wish** |
| rio (case 8) | the payload is not the payload | the array arm's sink refusal | declare the sink readonly |

rio types his query's input as `FrozenDeep<Payload>`, and it compiles — one line, the path the sdk
already recommends.

### the aha

> **the fix is real, and it is not the only wall.** one common field past the reported shape sits a
> second refusal with a different remedy.

⇒ that second refusal is **correct** — rio was about to hand a frozen array to a function that
could mutate it.

⚠️ **the diagnosis is buried, not hard.** the message names the field on line 2 and the cause on
line 3. the obstacle is line 1: a four-level expanded type the eye slides off. the message fails on
**length**, never content.

## .the bdd sketch — one walk, five boundaries

```gherkin
given a payload with a branded primitive at depth four, and an array beside it
  and the invoke slot is typed FrozenDeep<Payload>

  [t0] when the author reads the branded primitive at depth four
       then it is still a Stamp                                      # the fix, at depth

  [t1] when the author forwards the ARRAY-FREE variant to a mutable sink
       then it compiles                                              # the fix unblocks it

  [t2] when the author forwards the SAME payload plus one array field
       then tsc refuses                                              # the second wall
        and the cause is the array, never the brand

  [t3] when the author declares the sink readonly instead
       then it compiles                                              # the cooperative path

  [t4] when the author writes at depth four, or pushes to the array
       then both are refused                                         # the guarantee, intact

  [t5] when the author forwards the ARRAY-FREE SUB-OBJECT to a mutable sink
       then it compiles                                              # the fail-safe
        which proves `tags` is the ONLY incompatible member
        exactly as the error message's second line claims
```

```ts
type Stamp = string & { _dglo: 'iso-time.IsoTimeStamp' };

interface PayloadReported  { page: { range: { since: { lastMessageAt: Stamp } } } }
interface PayloadWithArray { page: { range: { since: { lastMessageAt: Stamp } } }; tags: string[] }

declare const reported:  FrozenDeep<PayloadReported>;
declare const withArray: FrozenDeep<PayloadWithArray>;

// [t0] — the brand survives four levels down
const deepStamp: Stamp = reported.page.range.since.lastMessageAt;

// [t1] — the reported shape forwards cleanly. THIS is what the wish buys
const queryReported = (_input: PayloadReported): void => undefined;
queryReported(reported);

// [t2] — 🔴 one array field, and the forward is refused. the brand is NOT the cause
const queryWithArray = (_input: PayloadWithArray): void => undefined;
// @ts-expect-error - the nested readonly array refuses the mutable sink
queryWithArray(withArray);
const stampStillFine: Stamp = withArray.page.range.since.lastMessageAt;   // ← proof of cause

// [t3] — the cooperative path
const queryReadonly = (_input: FrozenDeep<PayloadWithArray>): void => undefined;
queryReadonly(withArray);

// [t4] — the guarantee holds throughout the dense shape
// @ts-expect-error
withArray.page.range.since.lastMessageAt = '' as Stamp;
// @ts-expect-error
withArray.tags.push('x');

// [t5] — the fail-safe. the message says `tags` is the incompatible member; prove it.
// the array-free sub-object goes into the same kind of mutable sink, and compiles
const queryPage = (_input: PayloadWithArray['page']): void => undefined;
queryPage(withArray.page);   // ✅ compiles — the brand path is wholly compatible
```

🔴 **`[t2]` + `stampStillFine` earn this case.** the `@ts-expect-error` alone reads as "the fix did
not work". the line beneath proves the brand intact and isolates the array. no other case can tell
those two explanations apart — the diagnosis rio made by hand.

## .does the sharp edge fail safe?

graded against the **measured** message:

| property | verdict | the evidence |
|----------|---------|--------------|
| **fast** | ✅ | author time, at the keyboard |
| **loud** | ✅ | the build fails; a type refusal cannot be swallowed |
| **teaches the fix** | ✅ | names the **field** (`Types of property 'tags' are incompatible`), the **cause** (`is 'readonly' and cannot be assigned to the mutable type`), and prints the source type — the remedy is the message in the imperative |
| **refutes the misdiagnosis** | ✅ | 🔴 line 1 prints `readonly lastMessageAt: Stamp` — the error disproves "the fix did not land" |

### the residual

the message never says *"declare your sink as `FrozenDeep<T>`"*; a reader who does not know the
readonly/mutable rule may not step from cause to edit. two closers, both required:

| closer | reach |
|--------|-------|
| **`[t5]`** — proof that `tags` is the only incompatible member | the demo itself |
| **the jsdoc sink bound** (F4, a done-when) | one hover from the author's `FrozenDeep<Payload>` line |

⚠️ the jsdoc is in-band in an editor and out-of-band in ci. the grade rests on the message's own
three lines; the jsdoc is the belt beside that brace.

## .why it is a critipath

- **freq** — an array beside a branded primitive is the ordinary shape of a filter payload. any
  adopter with one meets this.
- **cost** — **misattribution.** rio concludes the fix did not land and heads to the wrong repo,
  the wrong changelog, maybe a pnpm patch no longer needed. ⚠️ the cost is self-inflicted — the
  error's first line says `lastMessageAt: Stamp` — so the remedy is "teach the read" (this case),
  not "fix the message" (out of reach).
- **density** — five boundaries in one walk: the primitive arm at depth, the object arm, the array
  arm, the sink bound, the write refusal. the highest-value, highest-risk demo in the set.
