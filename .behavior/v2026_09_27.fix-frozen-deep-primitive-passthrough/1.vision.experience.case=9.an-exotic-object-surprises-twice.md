# case 9 — an exotic object surprises twice, once each way

> ⚠️ **a declared composite file.** two experiences, each with its own feel × care:
>
> | cell | anchor | feel | care | the experience |
> |------|--------|------|------|----------------|
> | **A73** | `[t0]`–`[t1]` | happy | alter | a `Date` round-trips both directions |
> | **A77** | `[t2]` | sharp | alter | a `Map`'s `.set` compiles on a frozen value — under #48's type |
>
> both are F3's evidence. `[t2]` is the **before** half of F3's clamp.

## .why it is composite, and the weakest of the composites

case 8 earns its composite as a **dense walk** — one journey across quadrants, which
`boundary-density` sanctions. this file has no such defence: a `Date` round-trip and a `Map.set`
share a shape value and no thread. it stays one file because both halves are F3's evidence; the
header table and the inventory index keep the split unambiguous. `[t0]`–`[t1]` and `[t2]` share no
setup beyond the type, so a later split is clean.

## .why this case exists

cases 1–8 are critipaths. an alterpath demo is a bonus — its absence is a nitpick. this one exists
because it is **F3's evidence**: a decision about `Map` and `Date` reads better as a walk than a
table row. case 10 is the same for F9.

## .the narrative

ada has a domain object that is not json: a `Date` for the observation, a `Map` for a per-channel
lookup. she wraps it in `FrozenDeep` and expects "deep readonly" to mean what it says.

**the first surprise is pleasant.** she braces for the `Date` to be mangled — a mapped type over a
class usually is — and it is not:

```ts
const at: Date = frozen.observedAt;    // ✅ compiles
```

every member of `Date` is a **method**, so `readonly` lands on no slot that matters, and the type
round-trips both directions. no workaround needed.

**the second surprise is not.** under #48's type she reaches for the `Map`, braced for a refusal:

```ts
frozen.byChannel.set('sms', 3);        // ✅ compiles. she expected ⛔
```

the object arm maps over `Map`'s members, and `set` is a method — the mapped type keeps it, and
`readonly` on a method refuses no call. the type says frozen and permits the mutation.

it matches the runtime:

> `Object.freeze(map)` does not block `map.set()` either. a `Map`'s entries live in an internal
> slot, not in properties.

⇒ #48's type is **honest**, and it is not what "frozen" sounds like. ada, the median reader, calls
it a bug.

### the aha

> #48's `FrozenDeep` is a **property**-level guarantee: total against a mutation through a
> property, silent against one through a method — because `Object.freeze` is.

⚠️ that is the `write-property` / `write-method` split on the operation axis — the honest bound on
the word "frozen" under #48.

## .the bdd sketch — #48's type as written

```gherkin
given a domain object that holds a Date and a Map

  [t0] when the author assigns FrozenDeep<Date> back to a Date
       then it compiles — happy, and better than she braced for   # A73, happy alterpath

  [t1] when the author assigns a Date INTO FrozenDeep<Date>
       then it compiles — the round trip closes both ways

  [t2] when the author calls a mutator method on a frozen Map
       then it COMPILES — sharp, and worse than she braced for    # A77, sharp alterpath

  [t3] when the author writes to a frozen PROPERTY on the same object
       then tsc refuses — the guarantee is real where it reaches

  [t4] when the author checks the runtime
       then Object.freeze permits map.set too — so type and runtime AGREE
```

```ts
// [t0] + [t1] — Date round-trips both directions (probe premises 7, 8)
const outOfFrozen: Date = {} as FrozenDeep<Date>;
const intoFrozen: FrozenDeep<Date> = new Date();

// [t2] — 🔴 the mutator survives the mapped type (probe premises 9, 10)
const frozenMap = {} as FrozenDeep<Map<string, number>>;
frozenMap.set('sms', 3);                     // compiles — deliberately asserted
const frozenSet = {} as FrozenDeep<Set<string>>;
frozenSet.add('sms');                        // compiles — deliberately asserted

// [t3] — a property on the same shape IS refused. the bound is a boundary, not a hole
// @ts-expect-error - the property arm still holds
({} as FrozenDeep<{ byChannel: Map<string, number>; label: string }>).label = 'x';
```

⚠️ `[t3]` keeps `[t2]` from reading as a general hole: the same object refuses a property write and
permits a method call — a clean line, not a leak.

## 🔴 .the shipped type — F3's verdict

the wisher ruled (2026-09-28): **close the method reach.** the shipped type adds a
`ReadonlyMap<FrozenDeep<K>, FrozenDeep<V>>` / `ReadonlySet<FrozenDeep<T>>` arm — the collection
refuses its mutators, and each entry is frozen deep, the same way the array arm freezes its items:

| | #48 as written | shipped |
|---|----------------|---------|
| `frozenMap.set('sms', 3)` | ✅ compiles | ⛔ refused — `set` is absent from `ReadonlyMap` |
| `frozenSet.add('sms')` | ✅ compiles | ⛔ refused — `add` is absent from `ReadonlySet` |
| `Date` round-trip | ✅ | ✅ unchanged |
| property write on the holder | ⛔ | ⛔ unchanged |

⇒ `[t2]` becomes the clamp's **before**: execution asserts both mutators under
`@ts-expect-error`, and proves the clamp bites — red against #48's object arm, green against the
shipped arm. the type is then stricter than `Object.freeze`, a safe direction the jsdoc states.

## .why it is an alterpath, not a critipath

*if this path broke, would a core usecase fail, or is there a workable fallback?*

- **`Date`** — if the round trip broke, ada writes `as Date` at one seam, or keeps an
  `IsoTimeStamp` (which the glossary rules prefer). workable ⇒ **alterpath**.
- **`Map`** — a consumer who needs a readonly map can declare `ReadonlyMap<K, V>` on the slot.
  workable ⇒ **alterpath**.

⇒ both sit off the hot path: **a lambda envelope is `JSON.parse` output, so no `Date`, `Map`, or
`Set` survives the wire.** they reach a consumer only on a shape never serialized.
