# 🌙 dream: export `ArrayWith` from the package root

**kind** = fix · **owner** = ehmpathy/type-fns · **caught** 2026-09-27 · **closed** 2026-09-29

> ✅ **closed** by `v2026_09_27.fix-frozen-deep-primitive-passthrough` (F7 overruled: export it
> here). `src/index.ts` now carries `export * from './types/ArrayWith';`.

## .the cue that fired

the `1.vision` stone of `v2026_09_27.fix-frozen-deep-primitive-passthrough` asserted that an
export line is load-bearing (case 6 `[t0]`). to justify that claim I read `src/index.ts` against
`src/types/` — and found a live instance of exactly the failure the claim describes.

## .the gap, precisely

`src/types/ArrayWith.ts` is authored and tested (`src/types/ArrayWith.test.ts` exists), it
compiles into `dist` — and it is **absent from `src/index.ts`**.

every other file in `src/types/` has its line:

```
src/index.ts:15  export * from './types/DropFirst';
src/index.ts:16  export * from './types/Empty';
src/index.ts:17  export * from './types/HasMaybe';
src/index.ts:18  export * from './types/Literalize';
src/index.ts:19  export * from './types/PickAny';
src/index.ts:20  export * from './types/PickOne';
                 ⛔ no './types/ArrayWith'
```

checkable: `import type { ArrayWith } from 'type-fns'` fails against the published package — the
name is not on the root. to a consumer, the type does not exist.

## .the shape of the fix

one line, in sorted position between `./guards/assure` and `./types/DropFirst`:

```ts
export * from './types/ArrayWith';
```

✅ **the omission is an oversight, and that is settled** — no need to re-investigate:

```
$ git log --diff-filter=A --format='%H %s' -- src/types/ArrayWith.ts
7855ac5 feat(array): expose ArrayWith type declaration

$ git show --stat 7855ac5
 src/types/ArrayWith.test.ts | +35
 src/types/ArrayWith.ts      | +24
 (no src/index.ts)
```

the author's stated intent was to **expose** it; the commit touches no `index.ts`. so the export
line was simply forgotten.

⚠️ the export is a **public api addition** — semantically a minor. commit it under a `feat:`
header so the `please-release` action cuts the right bump, and give it its own commit rather than
a ride-along.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **clean** ✅ — one line, no ripple, no caller
- **safe** ⚠️ — **no.** it adds public surface to a package on a release train, inside a route
  whose wish is a *fix* for one named defect

the measured reason: `rhx git.commit.bind get` reports `level: fix` for this branch, and
`git.commit.set` validates the header prefix against that bind. a minor change cannot be committed
at its true level here — it would ship under a `fix:` header that understates it, or under a
`feat:` header the bind refuses.

⇒ clean passes, safe does not, so it defers — and the deferral is a judgment, so it carries a
fulcrum: `F7` in
`.behavior/v2026_09_27.fix-frozen-deep-primitive-passthrough/.fulcrums/`, at **90%**.

⚠️ the 10% is a live judgment for the council: a reviewer who holds the bind should be re-bound
rather than obeyed would be right to overturn the defer, and the fix is one line.
