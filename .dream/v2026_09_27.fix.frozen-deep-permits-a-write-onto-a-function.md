# 🌙 dream: `FrozenDeep` permits a property write onto a function

**kind** = fix · **owner** = ehmpathy/type-fns · **caught** 2026-09-27 · **closed** 2026-09-29

> ✅ **closed** by `v2026_09_27.fix-frozen-deep-primitive-passthrough` (F6 overruled: close it).
> the intersection sketched below keeps each prop writable — a prop is readonly in an intersection
> only where every member marks it so. the shipped arm is `FrozenFunction<T>` in
> `src/types/FrozenDeep.ts`: a function with no own props passes through whole; one with props is
> rebuilt from `Parameters` / `ReturnType` plus a readonly prop map. clamps:
> `FrozenDeep.test.ts` (functions) and `asFrozenDeep.test.ts` (function prop write throws).

## .the cue that fired

the experience decomposition for `FrozenDeep` walked `shape × operation × depth` and produced
cell **A17** — `function × write × top`. no free-list would have produced it; the grid did, and it
turned out to hold a real type/runtime disagreement.

## .the gap, precisely

the function arm returns `T` unmapped:

```ts
T extends (...args: never[]) => unknown ? T : …
```

that is correct — to map over a function discards its call signature. the consequence is that the
type places **no** `readonly` on a function's own properties:

```ts
const fn = {} as FrozenDeep<(a: number) => void>;
(fn as never as { tag: string }).tag = 'x';   // the type permits it
```

meanwhile `Object.freeze` **does** freeze a function, so the runtime refuses that write and throws
in strict mode.

⇒ the type is **more permissive than the mechanism** — the same class of defect as the
branded-primitive bug this wish fixes, pointed the other way.

checkable: assert the write is refused and it will fail until the arm is changed.

## .the shape of the fix

an intersection that keeps the call signature and adds readonly keys:

```ts
T extends (...args: never[]) => unknown
  ? T & { readonly [TKey in keyof T]: FrozenDeep<T[TKey]> }
  : …
```

⚠️ **this is not a one-liner to land unverified.** confirm against `tsc` that:

- the call signature survives the intersection (`fn(1)` still type-checks)
- `keyof T` on a function does not drag in `Function.prototype` members in a way that breaks
  assignability of ordinary functions
- a plain function with no own properties still round-trips both directions

and add a clamp per `rule.require.clamp-edge-cases`: remove the intersection, watch the write
assertion go red.

## .why it is not done in this round

the reach is near zero today and the fix carries real design risk:

- no reported shape has a function in it. a lambda envelope is `JSON.parse` output, and
  sdk-aws-lambda's own jsdoc says *"no field of this envelope is a function"*
- a function with meaningful own properties is a pattern from older js; typed code reaches for a
  class or an object with a method
- the fix needs its own verification and its own clamp — a second wish's worth of care for a case
  with no reported caller (`rule.prefer.wet-over-dry`)

⇒ the deferral is a judgment, so it carries fulcrum `F6` in
`.behavior/v2026_09_27.fix-frozen-deep-primitive-passthrough/.fulcrums/`, at 85%.

⚠️ **F6 names the uncomfortable parallel honestly**: *"no envelope of ours has one"* is precisely
the sentence that let the branded-primitive defect ship. the difference leaned on is direction —
branded primitives are common and on the rise across ehmpathy; functions with own properties are
rare and in decline. that is a judgment, not a measurement.
