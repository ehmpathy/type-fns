# 🌙 dream: sdk-aws-lambda delegates its freeze to `asFrozenDeep`

**kind** = reseed · **owner** = ehmpathy/sdk-aws-lambda · **caught** 2026-09-27

## .the cue that fired

type-fns' `v2026_09_27.fix-frozen-deep-primitive-passthrough` ships `FrozenDeep` and its runtime
companion `asFrozenDeep` (fulcrum F2, overruled 2026-09-29). the sdk carries its own copy of both.

## .the gap, precisely

one rule — *"a primitive has no interior; leave it alone"* — lives in two repos:

```ts
// ehmpathy/sdk-aws-lambda — setEventFrozen.ts:42
if (value === null || typeof value !== 'object') return;
```

and in type-fns' `FrozenDeep` + `asFrozenDeep`. the defect #48 fixes was a disagreement between a
type and a freeze kept apart, with no mechanism to compare them. a local copy keeps that seam open.

## .the shape of the fix

in sdk-aws-lambda's step 2, beside the type import:

- delete the local `FrozenDeep` and `setFrozenDeep`
- `setEventFrozen` becomes `return asFrozenDeep(input.event);`
- keep the sdk's jsdoc on why the envelope freezes; the mechanism now lives in type-fns
- ⚠️ behavior change to check: `asFrozenDeep` refuses `map.set()` at runtime (F12). no lambda
  envelope holds a `Map` (json has none), so no handler should notice — verify with the sdk suite

## .why it is not done in this round

another repo, and it waits on the type-fns release. it rides sdk-aws-lambda's step 2.
